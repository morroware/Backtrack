# Backtrack 0.7.3

This update replaces the acceleration-based gesture detector introduced in
0.7.2. That detector could reject intentional follow-up swipes after closing a
tab, leaving Back navigation unresponsive for several seconds.

## What changed

- Use the browser's native `WheelEvent.momentum` signal to separate direct
  input from trackpad inertia. No special low-to-high intensity ramp is needed.
- Finish an eligible Back gesture when inertia begins. If no inertia follows,
  finish after 220 ms without direct input. There is no post-action cooldown.
- Ignore inertia in the newly active tab so one swipe cannot cascade through
  multiple pages or tabs. Stop early tab closure while direct input continues.
- Cancel incomplete input when a tab is hidden, and retain duplicate-ID and
  overlapping-input protection across background-worker restarts.
- Preserve native browser Back when the required momentum signal is absent.
- Add local phase and gesture-correlation diagnostics without clearing existing
  logs or collecting page content or full URLs.

The positional behavior introduced in 0.7.0 is unchanged: traverse page history
first, then close the current tab and select the tab immediately to its left.
At the entry of the last tab, close that window, not the Brave application.
Pinned tabs and unclear history states remain protected.

## Compatibility and update

Automatic gestures require `WheelEvent.momentum`, introduced in Chromium 151.
The development Brave/Chromium 153 exposes this signal. Older or unsupported
browsers retain native Back but do not receive automatic Backtrack tab closure.
Protected browser pages, extension-store pages and browser error documents
remain outside the extension's reach.

Extract `backtrack-0.7.3.zip`, open `brave://extensions` or `chrome://extensions`,
then reload the existing unpacked extension or load the extracted directory.
Verify version **0.7.3** and refresh pages already open before the update.
Keep the existing installation identity if you want to retain calibration and
the development log.

## Verification

- 262 automated tests pass, including raw wheel input through content scripts,
  message handling, the gesture gate, tracked history and positional actions.
- Coverage includes abrupt, gradual and modest strokes; inherited inertia;
  immediate follow-up Back; sequential tab/window closure; unsupported input;
  page-owned scrolling; cancellation; and persistence across worker restarts.
- A physical two-finger Brave/macOS regression on September 22 confirmed child
  closure followed by Back in the previous tab on the next deliberate swipe.
  Both used the native momentum boundary. The second stroke began 644 ms
  after the child was removed; no repeated attempt or gate rejection occurred.
  The background actions took 60 ms and 2 ms respectively (not total gesture
  latency). The visible page moved from `?step=2` to `?step=1`.

The 220 ms no-inertia fallback cannot observe actual finger contact. Broader
compatibility across sites, browser versions and trackpads still needs testing.
Sequential three-tab/window closure and the no-inertia fallback are covered
automatically; this focused physical run did not re-test those cases.
The bounded local development log remains 400 actions plus 1,600 context events;
nothing is sent to a server.
